# Keplar Studio design system

`src/components/app-ui/studio-mode/ui/`. Import everything from the barrel:

```tsx
import { StudioRoot, Button, IconButton, Icon, MorphIcon, Tabs } from "@/components/app-ui/studio-mode/ui";
```

The direction: minimal, monochrome first, built to look engineered rather than decorated. The design system has no glass, blur, gradients, glow or overshoot. The accent appears only where it means something (selection, focus, progress). Both themes are complete, and the system uses the standard cursor. `tests/studio-ui-tokens.test.ts` enforces the colour and styling rules.

## 1. Root and theming

Render every Studio screen inside one `<StudioRoot>`:

```tsx
<StudioRoot paint>              {/* paint = fill with --ks-bg (full pages). Leave it off in the transparent overlay window. */}
  <ToastProvider>…screen…</ToastProvider>
</StudioRoot>
<StudioRoot theme="dark">…</StudioRoot>   {/* pin a subtree to one theme */}
```

- `tokens.module.css` defines the tokens as `--ks-*` custom properties on the root element. Everything inside inherits them. That includes top-layer UI (Tooltip, Popover, Menu, Dialog, Toast), because those elements stay in the DOM under the root.
- Theme switching uses the site's own mechanism. `THEME_SCRIPT` in `src/lib/theme.ts` resolves dark/light/auto, using `prefers-color-scheme` for auto, and writes `<html data-theme>` before paint. The Studio palette is Light by default and switches to Dark under `:root[data-theme="dark"]`. `theme` sets `data-ks-theme` to pin a subtree.
- Focus: inside the root, the site's global focus cues (brightness filter, underline, background bar) are switched off. Every Studio control draws `--ks-focus-ring` on `:focus-visible` instead.
- `studioRootClass` and `srOnly` are exported for host elements and visually-hidden text.

## 2. Tokens

|---|---|

| Fills | `--ks-fill-hover`, `--ks-fill-active`, `--ks-fill-selected`. These are translucent, so they work on any surface. |
| Text | `--ks-text-1`, `--ks-text-2`, `--ks-text-3` (all at least 4.5:1 on every surface and fill), `--ks-text-disabled` |
| Lines | `--ks-border`, `--ks-border-strong`, `--ks-divider` |

| Primary | `--ks-primary-bg`, `--ks-primary-bg-hover`, `--ks-primary-text`: a monochrome inverse pill |
| Status | `--ks-success`, `--ks-warning`, `--ks-danger`, `--ks-info` (text-safe), plus `-subtle` backgrounds; `--ks-danger-solid`, `--ks-danger-solid-hover`, `--ks-danger-ink` |

| Elevation | `--ks-elev-1` (popovers), `--ks-elev-2` (dialogs, toasts), `--ks-scrim`. Level 0 is flat, and borders do the work. |

| Type | `--ks-font-sans` (the site's Google Sans, `--f-sans`), `--ks-font-mono` (IBM Plex Mono, `--f-mono`). Sizes: `--ks-text-xs` 11, `-sm` 12, `-base` 13, `-md` 14, `-lg` 16, `-xl` 20, each with a matching `--ks-leading-*`, plus `--ks-leading-code`. Weights: `--ks-weight-regular/medium/semibold`. Easing: `--ks-ease-standard`, `-enter`, `-exit`, `-spring` (a CSS `linear()` critically damped spring with no overshoot, generated by `springLinear()`). CSS-module naming rule: `src/styles/redesign.css` forces a shadow onto any `<button>` whose class contains `btn`, `button`, `cta`, `__primary`, `__secondary`, `__ghost`, `__pill`, `__tab`, `Chip` and similar. Don't use those in class names or in `.module.css` file names inside `ui/`. Express variants as data attributes instead. A test enforces this.

## 3. Components

All components are typed, keyboard operable and reduced-motion aware.

**Button** `variant: "primary" | "secondary" | "ghost" | "danger"` (default secondary), `size: "sm" | "md" | "lg"`, `loading`, `disabled`, `leadingIcon`, `trailingIcon`, `fullWidth`, and every `<button>` prop including `ref`.
`loading` shows the geometric ActivityIndicator, sets `aria-busy` and `aria-disabled`, and ignores clicks. The button stays focusable.
```tsx
<Button variant="primary" loading={applying} onClick={apply}>Apply changes</Button>
```

**IconButton** takes `label` (required: the aria-label and the tooltip text) and `icon`. Optional: `variant: "ghost" | "secondary" | "primary"`, `size`, `shape: "square" | "circle"`, `pressed` (for toggles: aria-pressed), `disabled`, `shortcut` (shown in the tooltip), `tooltip` (default true; turning it off doesn't remount the button), `tooltipSide`, and `ref`.

**Tooltip** `<Tooltip content shortcut? side? disabled?>{oneElement}</Tooltip>`. It appears on hover after 450ms (instantly while a nearby tooltip has just closed) and on keyboard focus. Escape, leaving the control, blur or a press hides it. The tooltip is linked to the control with `aria-describedby`.

**Popover** `open`, `onOpenChange`, `anchorRef`, `label`, `side`, `align`, `role`, `initialFocus: "first" | "last" | "surface" | "none"`. It's a non-modal top-layer surface. Escape closes it and returns focus to the anchor; a press outside or Tab closes it.

**Menu**, **MenuItem**, **MenuSeparator**, **MenuLabel**
```tsx
<Menu label="Session actions" trigger={(p) => <IconButton {...p} label="More" tooltip={!p.open} icon={<Icon name="more" />} />}>
  <MenuItem icon={<Icon name="copy" />} shortcut={["Mod", "D"]} onSelect={dup}>Duplicate</MenuItem>
  <MenuItem checked={inline} onSelect={toggle}>Show diff inline</MenuItem>
  <MenuSeparator />
  <MenuItem danger onSelect={del}>Delete</MenuItem>
</Menu>
```
Keyboard: ArrowDown or Enter opens the menu on the first item, ArrowUp opens it on the last. Inside: Up/Down (wrapping), Home/End, type a letter to jump. Escape closes and returns focus to the trigger; Tab closes. `open`/`onOpenChange` are optional, for controlled use. Don't add a "Soon" item: leave unavailable actions out, or disable them and say why.

**SegmentedControl** `label`, `value`, `onValueChange`, `options: { value, label, icon?, disabled?, ariaLabel? }[]`, `size: "sm" | "md"`, `fullWidth`. It's a radiogroup with a sliding thumb that can be interrupted mid-slide. Arrow keys move and select; Home/End work too.

**Tabs** + **TabPanel**
```tsx
<Tabs id="inspector" label="Inspector" value={tab} onValueChange={setTab}
      items={INSPECTOR_TABS.map((v) => ({ value: v, label: INSPECTOR_TAB_LABELS[v], count: v === "changes" ? changed.length : undefined }))} />
<TabPanel id="inspector" value="code" active={tab === "code"}>…</TabPanel>
```
Activation is automatic. Left/Right and Home/End move between tabs, and the underline slides. `INSPECTOR_TABS` is `["code", "viewport", "changes", "plan", "activity"]`. TabPanel `lazy` unmounts it while inactive; by default it stays mounted but hidden. `tabId` and `tabPanelId` build the ids.

**Panel**, **PanelHeader**, **PanelBody**
- `Panel`: `tone: "surface" | "inset"`, `flush` (no border or radius, to fill a split pane), `label` (a labelled region).
- `PanelHeader`: `title`, `subtitle`, `actions`, `leading`, `level`.
- `PanelBody`: `padded`.

**ResizableSplit**
```tsx
<ResizableSplit label="Resize inspector" orientation="horizontal" defaultSize={38} minSize={20} maxSize={70}
                collapsible="start" storageKey="studio.inspector">{[left, right]}</ResizableSplit>
```
- Sizes are the start pane's share, in percent.
- Pointer: drag with pointer capture. Dragging past half of the collapsible pane's minimum collapses it.
- Keyboard on the `role="separator"`: arrows move 2% (8% with Shift), Home/End jump to min/max, Enter collapses or expands. Double-click also toggles collapse.
- A collapsed pane is `inert`.
- With `storageKey`, the split persists `{v:1,size,collapsed}` to `localStorage["keplar.studio.split.<key>"]`. Reads and writes are in try/catch, and the stored value is read through `useSyncExternalStore`, so there's no hydration mismatch. `onChange(value)` fires after each change is committed.

**ToastProvider** / **useToast** `placement: "bottom-right" | "bottom-center" | "top-right"`. `useToast()` returns `{ show(opts): id, dismiss(id) }`.
- `opts`: `title`, `description`, `tone: neutral | success | warning | danger | info`, `action: { label, onClick }`, `duration` (ms; 0 means it stays until dismissed; default 5000, and 0 for danger), `id` (to replace a toast in place).
- At most 4 toasts are shown. Hovering or focusing a toast pauses its timer.
- Toasts enter and leave with a short slide and scale. They're announced politely; danger toasts use `role="alert"`.
- `useToast` throws outside a provider.

**Dialog** `open`, `onOpenChange`, `title`, `description`, `children`, `footer`, `size: sm | md | lg`, `dismissible` (default true), `initialFocus`. It's built on a native modal `<dialog>`. Focus is trapped (Tab wraps), Escape and a backdrop press close it, and focus returns to whatever was focused before it opened.

**Badge** `tone: neutral | accent | success | warning | danger | info`, `variant: subtle | outline`, `icon`. A badge always has text.

**StatusDot** `status: idle | running | success | warning | error | offline`, `label` (always announced), `hideLabel`. Each status has its own shape as well as its colour: ring, half ring, disc, triangle, diamond, and ring with a bar.

**Kbd** `<Kbd keys={["Mod", "K"]} />` renders ⌘ on macOS and Ctrl elsewhere, with a spoken label. `KeyCombo` with `plain` gives the bare text. The helpers `formatKey`, `spokenKey`, `detectPlatform` and `useKeyPlatform` are exported.

**Progress** `value`, `max`, `label`, `showLabel`, `valueText` (default "3 of 7"), `tone`. It's for real counts only and renders nothing unless `max > 0`. Use `progressRatio()` to compute the fraction.

**ActivityIndicator** `label`, `showLabel`, `size`. A short segment traces a square. Mount it only while real work is in flight. With `label=""` it's decorative.

**EmptyState** `icon`, `title`, `hint` (one line), `action`.

**Switch** `checked`, `onCheckedChange`, `label`, `hideLabel`, `disabled`, `describedBy`. It uses `role="switch"`.

**Checkbox** `checked`, `onCheckedChange`, `label`, `hideLabel`, `indeterminate`, `disabled`, `name`, `value`. It's a native input styled to match.

## 4. Icons

**Icon** `<Icon name="attach" size={16} label?="…" />`. It's drawn on a 24-unit grid with a 1.5 stroke, round caps and no fill. It's decorative unless you pass `label`.
Names (`ICON_NAMES`): attach, image, file, folder, history, sessions, settings, viewport, changes, plan, activity, terminal, warning, error, info, check, credit, link, more, drag-handle, roblox-studio, blender, close, plus, minus, arrow-up, arrow-right, chevron-down, chevron-right, external, copy, trash, undo, stop, play, search, code, diff, eye, cube, refresh.
The Roblox Studio and Blender marks are generic pictograms (a studded block and a wireframe sphere), not copies of either logo.

**MorphIcon** `<MorphIcon icon="menu" state={open ? "close" : "menu"} size={16} />`. `state` is type-checked per icon (`MorphIconState<"menu">`), and it must reflect a real state.
- How the morph works: the browser interpolates the SVG geometry with CSS `d` transitions, over paths that share the same command structure (a test proves this for every icon). If the state changes mid-flight, the icon reverses from its current geometry. The morph takes 220ms, with standard easing and no overshoot.
- Reduced motion: the new state appears instantly.
- Browsers without `d` transitions, such as Safari, show a clean swap.

| icon | states |
|---|---|
| `menu` | menu, close |
| `plus` | plus, close |
| `play` | play, pause |
| `send` | send, working (a still diamond with a centre point: a run is in flight, not a spinner), complete |
| `expand` | expand, collapse |
| `eye` | visible, hidden |
| `code` | code, diff |
| `refresh` | idle, active (turns only while active, and finishes its turn when the refresh ends) |
| `chevron` | collapsed, expanded |
| `build` | build, stop |
| `search` | idle, focused |
| `settings` | closed, open |

**UltimateMark** `<UltimateMark active={tier === "ultimate"} animateKey={selectionId} size={20} label="Ultimate+" />` is the mark for the Solar selector.
- When it activates: the disc morphs into a four-point star, the rays turn onto the diagonals as ticks, two thin rings draw in (one in each direction), and the set expands into place and settles on the no-overshoot spring. That's 900ms in total, and then it stays in a calm active state.
- The sequence plays when `active` turns true or `animateKey` changes, and never on first paint.
- It's monochrome (`currentColor`). Under reduced motion it shows the static active state.
