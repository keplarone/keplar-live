# Keplar One browser extension

Manifest V3 extension (Chrome and Edge). Ask Keplar about text you selected or the page you're on, or use **Search with Keplar One** (Keplar Lens): point at a picture, card or paragraph and click it (like Google Lens), or drag over any area, and the answer opens in a side panel, with follow-ups. The answer comes back with a summary of where the models agreed and differed. Lens asks once before its first search; after that a search sends the words in the area and a JPEG of it. Nothing is stored.

**Status:** built and tested locally. 0.1.0 was submitted to the Chrome Web Store by hand; 0.1.2 (click to search, and Connect instead of an API key) is ready as an update but **not** submitted yet: `STORE_LISTING.md` has every dashboard field, and `extension/store/` has the screenshots and promo tiles (`node scripts/extension-store-assets.mjs` regenerates them from the real extension). Firefox and Safari are not supported yet.

## Install for testing
1. `npm run build:extension` writes `extension/dist/keplar-extension-0.1.2.zip` (or load the `extension/` folder directly).
2. Chrome → `chrome://extensions` → turn on Developer mode → "Load unpacked" → pick the `extension/` folder (or unzip the build and pick that folder).
3. Click the extension and press **Connect Keplar**, then approve on keplar.one (signed in). Questions and searches use that account's credits. (Or open "Use an API key instead" and paste a key from Account → Developer API.)

## Auth (and why)
**Connect** (no key to create or paste): the extension starts a sign-in request (`POST /api/extension/connect` with a PKCE challenge) and opens keplar.one/desktop/connect, where the person, signed in, checks the code and presses Connect. The service worker polls `POST /api/extension/token` with the PKCE verifier, which never leaves the extension, and collects a Keplar **API key** for that person's own workspace, once. It is marked as a browser extension (`kind: "extension"`, scopes `ask` and `usage`): it spends the plan's credits like an app question, has the plan's per-key limits, does not count toward the plan's key allowance, is listed with a Disconnect button in Account → Developer API, and lasts a year (up to 5 browsers per account). Disconnect in the extension calls `POST /api/extension/disconnect`. Server side: `src/lib/api/extension.ts` (the sign-in steps are the desktop app's, `src/lib/desktop-auth`, as app "extension"). It deliberately does **not** use your signed-in browser session or cookies, and an extension approval can never be redeemed as a session: that would hand an extension your whole account. A key pasted by hand still works ("Use an API key instead").

## Privacy and permissions
- `activeTab` + `scripting`: after you click "Add selected text", "Add page text", "Search with Keplar One", or a context-menu item, read that tab's selection, page text, or the area you drag over or click (its words, and a picture of it captured from the visible tab). The same click draws the overlay. It does not run on other tabs, and it cannot see the rest of the screen outside the browser.
- `contextMenus`: "Ask Keplar One about the selection", "Ask Keplar One about this page", and "Search with Keplar One". `storage`: the connection key and the connected account's email (local), and a one-time menu → popup hand-off and the in-progress Connect request (session).
- No host permissions, no content scripts in the manifest, no remote code (`script-src 'self'`), no analytics. The only network destination is `https://keplar.one` (`/api/v1/ask`, `/api/v1/usage` for the credits line, and `/api/extension/*` to connect and disconnect). The ask body is the question text, plus for Lens the area's picture (`image`, after the one-time consent) and earlier turns (`history`). Questions, answers and pictures aren't saved by the extension. `node scripts/extension-lens-e2e.mjs` runs the whole Lens flow in a real browser and checks every request body.
- Pages are labeled to the API by host only (never the full address).

`scripts/build-extension.mjs` validates all of this (permission allow-list, CSP, no eval/innerHTML/remote URLs) before it writes the zip, and `tests/extension.test.ts` runs the same checks.

## Files
`manifest.json`, `background.js` (context menu, crop, ask stream), `lens.js` (overlay, injected on click), `popup.html/css/js` (UI), `lib.js` (pure helpers, unit-tested), `icons/` (generated by `tools/make-icons.mjs`, not shipped).
