# Keplar One repository audit, October 2026

Audited 2026-10-18 against `main` at `287a5b1` (PR #80, live on keplar.one). Updated 2026-10-19 for what landed on `main` up to `97e5900`: PR #81's audit fixes (`docs/engineering-audit-2026-10-19.md`), the `authorize()` gate for MCP calls, versioned side SQL setup, the production health check that fails without a database, and the Business Activity Center. This is Phase 0 of the master production directive. Every statement points at a file in this repository. Where something is labelled "partial" or "missing", that comes from reading the code, not from assuming. Nothing in this audit was checked against production data, live provider accounts or real payments.

Scale at audit time: 292 API route handlers (`src/app/api/**/route.ts`), 143 pages (`src/app/**/page.tsx`), 411 unit test files (`tests/*.test.ts`, about 3,100 tests), 49 Playwright specs (`e2e/*.e2e.ts`).

## 5. Technical debt

- **Very large modules.** `src/lib/orchestration/orchestrator.ts` is about 870 lines in one generator, and `src/lib/business/agents.ts` is 553. New behaviour is safest as pure modules called from them, which is how milestone 1 is built.
- **Three audit logs and several status unions** (see §3) that will need unifying before a shared task-state machine.
- **Runtime DDL** (R7) scattered across modules, with no single view of the schema.
- **Windows deploys**: `scripts/deploy.mjs` assumes Linux paths (`docs/security-progress.md`).
- **Catalog freshness**: prices are a dated snapshot. The `TODO(founder approval)` cost estimates are in `compute.ts`.
- **CRLF working tree on Windows** (`core.autocrlf=true`). Harmless, but scripted edits must normalise line endings.

## 7. First executable milestone

**Server citation check for Deep Research.** PR #81 shipped the base: each cited sentence is compared with what was read from its pages (the search's passage and the reading model's notes for that page), figures first and then content words. Statements are labelled supported, partly supported or not verified, and nothing is removed. Its "Citation check" list and header counts are covered by `tests/deep-research.test.ts` and `e2e/citation-check.e2e.ts`.

This PR adds two things #81's check lacked:

- **Conflicting figures.** If a cited page is on the same topic and gives a different figure for the same unit (the sentence says "300 metres", the page "330 metres"), the statement is now "conflicting", with the page's own wording quoted. #81's status type and ranking already had "conflicting", but nothing produced it. Unit words don't count toward the topic test.
- **Fuller page text.** The check compares up to 4,000 characters of the text the search returned for each page, not only the 280-character snippet the card shows. The fuller text stays server side and is never streamed or saved.

Code: `src/lib/research/citation-check.ts` (`conflictIn`, `PAGE_TEXT_CHARS`, `evidenceByPage`'s `pageText`), `src/lib/orchestration/research.ts` (keeps the fuller text), `src/lib/orchestration/types.ts` (optional `summary.conflicting`, so answers saved before this stay valid), and `src/components/app-ui/research/Research.tsx` (conflicts count toward "needs a closer look"; the existing "Source n says" line shows the quote). Tests are in `tests/deep-research.test.ts`.

Dropped while reconciling with #81: the first version of this PR also removed a citation marker whose page was clearly about something else. #81 decided that nothing is removed, so a paraphrase never loses its source; this PR keeps that rule (see `docs/DECISIONS.md`).

No database, auth, payment or deployment change.
