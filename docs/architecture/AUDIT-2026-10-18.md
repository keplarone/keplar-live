# Keplar One architecture audit

Inspected 19 October 2026 on `keplarone/keplar-live` at `287a5b1` (`Restyle Keplar One (Gemini-led) and Keplar Business (Apple-led)`). Read-only. No product code, schema, env values, or production deploy was changed.

This is a map of the repository as it is, not a target design. Where an older doc disagrees with the code, the code wins. `docs/accounts-billing.md` still says the Neon adapter has not been run against a live database; this audit did not read Vercel env values or query production, so that sentence is unverified either way.

## 1. What the system is

One Next.js application (`package.json` name `keplar-site`, Next `~16.3.8`, React 19) serves keplar.one, docs, the signed-in app, Business (`business.keplar.one`), and Space Studio (`space.keplar.one`). There is no separate backend service. Route handlers under `src/app/api` are the API. Persistence is Neon Postgres when `DATABASE_URL`, `POSTGRES_URL`, or `POSTGRES_URL_NON_POOLING` is a postgres URL (`src/lib/create/platform/neon.ts`); otherwise a JSON file store that is ephemeral on Vercel (`src/lib/create/platform/store.ts`).

Hosts are split in `next.config.ts` and `src/proxy.ts`. A request whose Host is not a Keplar host is rewritten to the published site for that custom domain, or 404. Nothing else of the app is reachable on a customer host.

UX gaps that are visible in routing and plan gates, not in a design pass:

- Site Create is removed from the UI. Deep links land on the App tab (`next.config.ts`).
- Keplar Wants and Keplar Browser are removed. Old URLs go to Ask. Their collections remain only so deletion still sweeps them (`src/lib/privacy/account-data.ts`).
- Business, Agents, and Approvals marketing/app URLs leave keplar.one for the business host, while the page files under `src/app/app/agents` and `approvals` still exist.
- Slides and video are plan-gated in the API, so a page that still shows the control will fail server-side. That is intentional (`src/lib/tools/access.ts`).
- The `app` i18n catalog is empty (`src/lib/i18n/loaders/available.ts`). The signed-in app is not translated. 24 locales have `client` and `marketing` catalogs (wave 1, marked stable). 101 have `common` (beta locales fall back to English). Consent strings exist for those 101.
- There is no in-app notification center. Owner alerts are email plus an optional webhook (`src/lib/accounts/alerts.ts`). Users see approval queues inside Business, not a notification inbox.
- Checkout copy stays "opens soon" until Whop keys are set (`docs/accounts-billing.md`). This audit did not check whether those keys are set in production.

## 3. Backend shape

- Edge: `src/proxy.ts`. Same-origin check on browser state-changing `/api` calls, 240 requests/minute per IP, 64 MB body cap, request id, custom-domain rewrite, locale hint.
- Handlers: `src/app/api/**/route.ts`. About 292 API route modules, plus OG, sitemap, and published-site routes.
- Tenancy: a workspace id. Signed-in users get `ws_` + hash of user id (`src/lib/accounts/workspaces.ts`). Teams are a second tenant id (`src/lib/team`).
- Jobs: Vercel Cron (`vercel.json`), Inngest (`src/lib/inngest`), and an in-store queue (`src/lib/create/platform/queue.ts`).
- Models: `src/lib/orchestration`, called from `POST /api/keplar` and `POST /api/v1/ask`.

`keplar_rows` indexes are fingerprinted (`SCHEMA_VERSION` in `neon.ts`). A matching marker skips DDL on cold start. Other tables have no shared migration version. A changed `CREATE TABLE` does not alter an existing column. There is no down migration.

### Collections inside `keplar_rows`

Every product record is a JSON document scoped by `workspaceId`. `src/lib/privacy/account-data.ts` is the inventory. `tests/privacy.test.ts` fails if a new collection is not classified as user data or retained.

User content (exported and deleted with the account, secrets redacted): chats (`chat_threads`), memory (`memory_items`, `memory_settings`), projects and files, sites and versions, leads, app builds, study sets and progress, slide decks, media jobs, Business CRM, orders, bank items, connector tokens, agent runs, approvals, audit rows, MCP server secrets, Space profiles (birth date, parent email), support tickets, feedback, specialists, family settings (PIN hash not exported).

Retained after deletion: Whop payments, billing events, Apple subscription rows, compute ledger, purchased credit packs, abuse reports, security events (hashes only, 90 days), cost events. The file comments say these hold ids and amounts, not chat text.

System rows (`system_*`, `admin_*`, `ops_*`) are cross-tenant and not a person's export.

Without `DATABASE_URL`, the file store is per instance. Plan state is also copied into a signed `keplar_plan` cookie (`src/lib/billing/plan-cookie.ts`). A cancel recorded on one instance is not visible on another until the webhook hits an instance that holds the row. Production needs Neon for shared plan, usage, and Create data.

`scripts/backup-db.mjs` exists. `docs/known-gaps.md` says it has not been restore-tested against production.

## 6. Authentication and authorization

Provider: Better Auth 1.7 (`src/lib/accounts/auth.ts`), not Auth.js. No Better Auth database adapter. The session cookie is the fast path. Neon rows make revocation real.

Methods:

- Magic link: HMAC token, 15 minutes, confirm POST so scanners do not consume it (`src/lib/accounts/magic-token.ts`).
- Email and password: own plugin, scrypt via Better Auth, hashes in `keplar_credentials`. Needs the database. 10–128 characters (`password-policy.ts`).
- Google and Microsoft: only if both client id and secret are set (`src/lib/accounts/oauth.ts`). Unverified emails refused. Provider tokens are not stored.
- Passkeys: `@simplewebauthn` (`src/lib/accounts/passkeys`). Treated as two factors. Server tests use a software authenticator. `docs/known-gaps.md` says a real device has not been tried.
- TOTP MFA: `src/lib/accounts/mfa`. Pending sessions are refused by `getSession`. Recovery is codes, then a human deleting `keplar_mfa`.
- Desktop pairing: `src/lib/accounts/desktop-auth.ts` and `keplar_desktop_auth`.
- Space Roblox and Business handoff: plugins in the same auth module.

Session: HttpOnly, SameSite=Lax, Secure on https, 60-day sliding cookie, or a session cookie when "keep me signed in" is off (`src/lib/accounts/session-cookies.ts`). `guardSession` checks the Neon row (about 15 seconds of per-instance cache). Neon down fails closed (`src/lib/accounts/session-guard.ts`). Sign-in rotates the session id. Password reset sets `sessions_valid_after` and signs other devices out.

Workspaces: one per user, created on first sign-in. Plan lives on the row. Admin emails (`src/lib/billing/admin.ts`) are treated as Business with unlimited credits and a daily USD cap (`KEPLAR_ADMIN_DAILY_USD_CAP`, default 25 in `.env.example`). A lapsed paid period (default 3 days grace, `KEPLAR_PLAN_GRACE_DAYS`) falls back to Free (`planLapsed`).

Teams (`src/lib/team/policy.ts`): viewer, member (Editor), admin, owner. Teams are offered on Business only in `TEAM_POLICY` (10 seats, 13,500 shared credits — marked founder-approval TODO). Routes that do not pass `team: true` ignore the team cookie, so billing cannot be pointed at a team by the client.

API keys and embed widgets are stateless: no memory, no chats (`via: "api" | "embed"` on the workspace).

Roles are not a global RBAC table. They are: admin email list, team role, Business teammate, plan entitlements (`src/lib/create/platform/plans.ts`).

## 7. Intelligence

### Intent

Two classifiers, neither is a trained router model.

1. Task class for model routing: `HeuristicClassifier` in `src/lib/orchestration/classifier.ts`. Regex over the prompt plus composer modes. Kinds include general, code, finance, strategy, research, analysis, writing, creation, factual, agent. Complexity drives panel size. The file says a production classifier would be a small model; this one is rules so the path is deterministic.
2. Product intent for the composer: `routeChat` in `src/lib/chat-actions/intent.ts`. Slash commands and phrase rules that open Study, Slides, apps, projects, or agent actions. This does not pick the model.

### Model router

`CostAwareRouter` (`src/lib/orchestration/router.ts`) scores catalog models as quality × reliability × latency ÷ cost, then builds a panel:

- simple: 1 model, no verifier
- moderate: 3, or 2 when the question is short (`isLightModerate`)
- complex: 5
- strategy fast/thorough changes the count, cap 6

Free (`PLAN_ALLOWANCES.free.models === "free-only"`): at most 2 panel models, no judge, only `$0` OpenRouter `:free` slugs (`src/lib/orchestration/free-guard.ts`). The registry refuses a Free call to any priced, non-`:free`, or non-OpenRouter model before the request is sent. Paid plans can use the full catalog.

`src/lib/orchestration/config.ts`:

- Live calls happen only when `KEPLAR_LIVE_MODELS` is exactly `1` and a key exists. Otherwise the engine returns the demo mock, even if keys are present.
- `KEPLAR_FORCE_MOCK=1` forces the mock.
- Free uses `OPENROUTER_API_KEY_FREE` if set, else `OPENROUTER_API_KEY`. Direct OpenAI, Anthropic, Google, xAI, NVIDIA, and LiteLLM keys are nulled for Free.
- Paid OpenRouter requests send `data_collection: "deny"`, ignore first-party DeepSeek, and pin fp8/bf16 on open weights (`OPENROUTER_PROVIDER_DEFAULTS`).
- Free defaults `data_collection` to `allow` (hosts may train). `KEPLAR_FREE_DATA_COLLECTION=deny` opts out and drops most free endpoints. While allow is on, `POST /api/keplar` must not attach saved memory or document text (comment in `config.ts`).
- Sensitive tier sets zero-data-retention and drops models that require provider retention.
- Optional direct keys: `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GOOGLE_API_KEY`, `XAI_API_KEY`, `NVIDIA_API_KEY`. Optional `LITELLM_BASE_URL` / `LITELLM_API_KEY`.
- Retrieval (web plugin) is off unless `KEPLAR_RETRIEVAL_ENABLED=true`. Engine is `exa` unless `KEPLAR_SEARCH_ENGINE=parallel`. Free never retrieves.
- `KEPLAR_LIVE_DAILY_USD_CAP` (default 5 in code) caps provider USD per UTC day across live calls. Separate from the product spend caps below.

Catalog: `src/lib/orchestration/catalog.ts` and `catalog.json`. Slugs are mapped in `config.ts` (`OPENROUTER_SLUG_OVERRIDES`). Learning can nudge scores by 0.8–1.3 after enough evidence (`src/lib/learning/active.ts`) and cannot bypass free, vision, or price filters.

Small talk is one free model on every plan and is not charged (`src/lib/orchestration/smalltalk.ts`).

### Context

- Saved memory: up to 100 notes, 220 characters, per workspace (`src/lib/memory/repo.ts`). On by default. Superseding facts replace older ones. Erase is hard delete.
- Chats: `chat_threads`, cap 200.
- Attachments and follow-ups: `src/lib/orchestration/followup.ts`, `answer-followup.ts`, `src/lib/attachments`.
- Project instructions and notes are a separate store (`src/lib/projects`), not a vector index.
- No embedding store or long-term retrieval index exists in this repo.

### Research

`src/lib/orchestration/research.ts`. Paid plans only, not the Sensitive tier, and only when retrieval is enabled and the estimate fits the allowance. Three queries, pages read, notes, then the panel. Citations that do not match a page that was read are stripped. If search is off, the answer says the models did not read pages.

Desktop Live Research is a different path: `src/lib/desktop/research-bridge.ts`. The desktop app (0.2.0+) searches and reads on the person's machine. The site still writes the answer through `/api/keplar`. A normal browser has no bridge. `KEPLAR_LIVE_RESEARCH_OFF=1` ignores the desktop brief. Citation check on the desktop is lexical (`docs/known-gaps.md`).

### Reasoning, debate, synthesis

`src/lib/orchestration/orchestrator.ts` runs the panel, then compare (`comparator.ts`), verify (`verifier.ts`), and synthesize (`synthesizer.ts`). A judge runs when the panel disagrees on complex routes. `quality-gate.ts` drops empty, looping, or non-word answers before they are shown or billed. `disagreement-guard.ts` keeps disagreement visible in the markdown.

Debate (`src/lib/orchestration/debate.ts`, marked BETA): 2 models × 2 rounds on Free (counts as 2 free questions), 3 × 3 on paid. The last round goes through the normal compare and synthesize path. Nothing is stored as training.

Structured blocks: the writer may append one `keplar-ui` fence parsed by `src/lib/rich-answer`. Types include ranked, compare, cards, timeline, steps, pros/cons, stats, callout, sources. Agreement counts are filled by the server, not the model.

Quiz in an answer: `src/lib/quiz/schema.ts` (Zod). A bad question is dropped. No valid question means no quiz; the markdown remains. Study quizzes are a different store (`/api/study/sets/[id]/quiz`).

### Quality evaluation

What exists:

- Deterministic output gate (`quality-gate.ts`) and unit tests around answer shape, honesty, and disagreement.
- Comparator disagreement summary on the answer card and on `/api/v1/ask`.
- AI Critic for a creation (`src/lib/critic`, `/api/critic/[id]`), not for chat answers.
- Keplar Core self-dev loop (`src/lib/core/selfdev`: variants, eval runs, proposals) behind admin and `/api/cron/core`. It is an internal experiment harness, not a gate on user traffic.
- Learning arms (`src/lib/learning`) adjust routing weights. They do not score a held-out set on each deploy.

What is absent: a production eval that blocks a model or prompt change, and a model-based classifier.

## 8. Execution

### Workflow planner and agent orchestrator

There is no general workflow planner for chat. Business agents (`src/lib/business/agents.ts`) run a stored agent definition: trigger, tools, caps. `runAgent` is the orchestrator. Event and schedule triggers always queue outbound actions for approval (`forceApproval`). A chat-created agent goes through `/api/business/agents/from-chat`.

`src/lib/core/jobs.ts` is a separate background job record for Keplar Core (question, notes, result, 7-day expiry). It is not the user-facing agent runner.

### Tool registry

There is no single registry every chat turn consults. Tools are split:

| Path | Role |
|---|---|

| Composer | `src/lib/chat-actions` routes the message to a product surface. It does not execute an external tool. |

MCP popular servers are listed in `src/lib/mcp/popular.ts` (Context7, DeepWiki, docs, and OAuth betas for Linear, Notion, Sentry). `docs/known-gaps.md` says connectors have not been run against real accounts.

### Browser automation

- User code (JS/Python) runs in the person's browser: opaque iframe, worker, time and output caps (`src/lib/sandbox/runner.ts`). Not on Keplar's servers.
- Site QA and app-build checks launch Chromium via `@sparticuz/chromium` and `playwright-core` inside the function (`next.config.ts` traces those binaries into `/api/sites/[id]/qa` and `/api/apps/[id]/build`).
- Business computer use (`src/lib/business/computer.ts`): the desktop sends a screenshot; the server proposes one action; the app asks the person before spend, send, delete, submit, or sign-in. The server never moves the mouse.
- Vercel Sandbox microVMs (`@vercel/sandbox`) back Blender Cloud and related render machines (`src/lib/blender-cloud/machine.ts`), using the deployment OIDC token. `VERCEL_SANDBOX_TOKEN` is the documented fallback in `src/lib/create/platform/config.ts`.

There is no server-side browser agent that clicks the public web on the user's behalf.

### Background jobs

| Mechanism | What runs |
|---|---|
| Vercel Cron `vercel.json` | Domains, learning, agents, OpenRouter balance, cost guard, core, roblox-cloud, blender-cloud, observatory, app schedules, space stats. All daily, not sub-minute. |
| Inngest `src/lib/inngest/functions.ts` | Agent schedule every 5 minutes, one scheduled run, one event run, telemetry retention. 503 when keys are absent. `KEPLAR_LOCAL_SCHEDULER=1` ticks in process. |
| `queue.ts` | `defineJob` is used for `media.run` (`src/lib/create/media.ts`) and `agent.run` (`agents.ts`). `agent.run` is handed to Inngest when Inngest is on. Other jobs are rows in `queue_jobs`, started with `after()`, leased, reaped when the lease expires. |

Cloud workers (Roblox, Blender) call themselves with `CRON_SECRET` so a long job continues across invocations.

- Answer: quality gate, citation stripping, disagreement guard, quiz schema.
- Creation: critic, site QA browser, app-builder verify (`src/lib/app-builder/verify`).
- Agent: firewall plus approval row before an outbound effect (`biz_approvals`).
- Billing webhooks: signature and idempotency row (`billing_events`, `whop_payments`, `apple_billing_events`).

|---|---|---|---|---|
| Free | $0 | None. About 50 questions/day, fair use. | `:free` only | No |
| Lite | $20, hidden until `WHOP_PLAN_LITE` | 2,400 | All | No |
| Plus | $45 | 6,000 | All | Yes |
| Pro | $99 | 13,500 | All | Yes |

Checkout: `POST /api/billing/checkout` creates a Whop checkout configuration and returns only a whop.com URL. Webhook `POST /api/webhooks/whop` grants or revokes the plan. Idempotent on webhook id.

Apple: `POST /api/billing/apple/verify` (session) and ASN V2 `POST /api/webhooks/apple`. 503 until `APPLE_BUNDLE_ID` or `APPLE_IAP_ENABLED`. Product ids in `.env.example`: `one.keplar.plus.monthly`, `one.keplar.pro.monthly`.

## 14. Limitations and risks

1. Schema is implicit. A new column in a `CREATE TABLE` string does not migrate old rows. `keplar_rows` is schemaless JSON, so a bad write is a bad document, not a rejected row.
2. Two sources of plan truth: the workspace row and the signed plan cookie. They diverge when the database is down or the webhook hits a different instance.
3. Free traffic can be sent to hosts that train, by default. The privacy gate depends on every call site remembering not to attach memory.
4. The classifier cannot tell a hard question from a keyword miss. Routing quality is only as good as the regex plus the catalog scores.
5. Tool use is not one gate. Chat, MCP, connectors, computer use, and publish each check permissions in their own file. A new tool can ship without an approval step.
6. Jobs are split across Cron, Inngest, and `queue_jobs`. Only two job names are registered on the in-store queue. A third subsystem will be easy to add and easy to forget in the reaper.
7. Object storage is Postgres bytea or ephemeral disk. Large media and backups compete with the database.
8. Observability stops at Vercel logs plus an optional, unproven Sentry forwarder. A silent cron failure is a missed heartbeat, not a page, unless someone reads `/admin`.
9. Billing figures in `plans.ts` and team caps are marked TODO(founder approval). Shipping them is a product decision already encoded, not a separate config service.
10. Generated-app end users (`app_users`) are a second identity system with its own passwords. Deleting a Keplar account must delete those apps' rows; the privacy file says it does. A bug there leaks a tenant's customers.
11. Admin is an email allow-list. MFA for admin is off until `KEPLAR_ADMIN_REQUIRE_MFA=1`, so a stolen session cookie for that inbox is admin.
12. `owner()` on several Business routes does not require a Business plan. Safety depends on later entitlement checks. A missed check exposes the handler to every signed-in user.

## 16. Where a security gate would sit

The closest thing to a central check is already split in two:

- `inspectAction` in `src/lib/business/firewall.ts` returns risk, reasons, a block string, and whether auto-send is allowed.
- The MCP gateway (`src/lib/mcp/gateway.ts`) is the only path that chains policy, firewall, approval, budget, and audit for a tool call.

Everything else re-implements a slice. `runAgent` inserts `biz_approvals`. `computer.ts` sets `sensitive` and trusts the desktop to ask. Publish checks team role in the route. Account export emits `export.data`. Checkout checks `requireAccount` and rate limit, not a shared action type.

A gate that matches this code would be a function next to `src/lib/security/events.ts`, for example `authorize({ actor, workspace, action, resource })`, returning allow, require approval, or deny. It should call the existing firewall for outbound payloads, `roleCan` for team actions, and `ENTITLEMENTS` for plan limits, then write one `security_events` row and, for Business, the existing `biz_audit` row. It should not replace `getSession`.

Call it first from:

1. `runAgent` in `src/lib/business/agents.ts` (replace the inline auto-send boolean).

## 18. Decisions that need the owner

These touch production data, the auth provider, payments, infrastructure, or real spend. Do not implement them on an agent's own judgment.
