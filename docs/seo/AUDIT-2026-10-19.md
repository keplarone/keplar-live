# SEO audit, 19 October 2026: baseline, status by finding, the agents' report, and its review

This file has three parts. **Part A** (this section) states the baseline and the status of every High finding at the end of branch `claude/seo-intent-engine`. **Part B** is the audit report the workflow's synthesis agent wrote from the 13 dimension audits and 32 verifier verdicts, unedited. **Part C** is the completeness review a critic agent wrote about Part B, unedited, followed by the responses.

**Baseline.** The dimension agents read `keplar-live` at `origin/main@1c011fe` (the parent of this branch) and, for some dimensions, the working tree while the first fixes were landing (commit `587f7ef`, then `175ab02`). The verifiers ran after those fixes. So in Part B a "refuted" verdict usually records that the fix was already in the tree, not that the finding was wrong on `main`; the review in Part C says the same and is right. Part A gives the status each finding has at the end of this branch, which is the state that matters.

**Method.** The audit ran as an orchestrated workflow (`docs/seo-engine/audit-workflow.js` in `keplar-main`, run `wf_1f993f99-212`): 13 audit agents, one per dimension, each inventorying its area from the code and the production HTML and listing findings with severity, files, evidence, impact, recommendation and effort; 32 verifier agents, one per Critical or High finding (capped at four per dimension), each re-reading the cited files and returning a verdict; one synthesis agent; one critic agent. Severity scale: Critical (indexing or security regression on live pages), High (measurable loss of discovery, trust or conversion), Medium (quality or consistency gap), Low (housekeeping).

**What this document does not do.** It claims no traffic, ranking, impression or index figures. Search Console is not connected; nothing here estimates what it would show.

## 1. Routing and indexability

- **RI-1 High. Unapproved `/vs/perplexity` indexable.** Refuted by the verifier: `vs/[slug]/page.tsx` already passed `noindex: true` when `approved` is false. **Fixed** the residue: `tests/launch-readiness.test.ts` and `tests/seo.test.ts` now assert the guard, and the stale "still indexable" comment in `src/lib/kb/vs.ts` is gone.
- RI-2 Medium. Sign-in, sign-up, password, verify, `/embed` and the `/app` tab shells answer 200 with a self-canonical and no robots meta. The `X-Robots-Tag: noindex` header for these paths is sent on the keplar.one host (`next.config.ts`), which the agent did not weigh. **Open**: add `noindex` in page metadata as well so the directive does not depend on the host header.
- RI-3 Medium. 77 beta locales publish partly-English pages outside hreflang and the sitemap, linked from every page. **Owner**: either `noindex,follow` for non-stable locales or canonical to the English URL; both lose the beta pages from the index on purpose.
- RI-4 Medium. `/{locale}` translates `/overview` but its hreflang cluster pairs it with the chat at `/`. **Owner**: move the localized overview to `/{locale}/overview` or localize the chat home.
- RI-5 Medium. `/`, `/overview`, `/product`, `/what-is-keplar`, `/how-it-works`, `/simulation`, `/keplar-one` all answer "what is Keplar". **Partly**: descriptions rewritten to distinct angles; merging or redirecting pages is an owner call.
- Low: `/enterprise` and `/agents` redirect with 307 and keep lastmod dates; www redirect chains; `/status` and `/feedback` missing from the sitemap; `/answers` and `/topics` hubs indexable when empty.

### Executive summary

1. The SEO infrastructure is sound and should not be rebuilt: pageMeta() self-canonicals, a 342-URL sitemap with real lastmod on every entry and zero duplicates, three dynamic family sitemaps that 503 rather than publish empty, correct hreflang for 24 stable locales, one escaping JSON-LD component, prices only from tiers.ts, and 83/83 SEO unit tests passing.
2. No Critical finding exists; nothing observed misstates prices or founders, leaks private data, or blocks crawling of a page meant to rank.
3. The largest confirmed High-severity problem is factual drift in what machines read: product-facts.ts (feeding llms.txt, llms-full.txt, capabilities.json and the SoftwareApplication featureList) says web search is "not switched on yet, paid plans when live", while features.ts, tiers.ts and /pricing say Live Research is in beta on every plan in the desktop app, and a dozen docs dated 3 October still say Keplar does not browse at all (ASF-1, ASF-2).
4. Four of the seven AI-backed free tools accept 7,000 to 9,000 characters while the Free lane rejects composed prompts over 6,000, so the long-input visitor the copy invites ("about 1,500 words") gets a 413 telling them to upgrade (FT-1, confirmed by composing each prompt at maximum size).
5. The home page HTML is 89 bytes of visible text plus six links (the whole body is client-rendered behind BAILOUT_TO_CLIENT_SIDE_RENDERING); a newer source adds one lede sentence, but non-JS fetchers and answer-engine crawlers still see almost nothing on the root URL (PR-1).
6. No search-side data source exists anywhere in code: impressions, clicks, CTR, position and submitted-vs-indexed counts have no integration, and GOOGLE_SITE_VERIFICATION / BING_SITE_VERIFICATION are absent from the Vercel project's 62 environment keys; the admin page says so itself (M-2).
7. Nine findings were refuted on the evidence, mostly because commit 587f7ef already did what they recommend: per-cluster product CTAs via productCta(), expanded Study and Slides hubs (~740 and ~560 words), footer TOPIC_LINKS to every cluster hub, noindex on unapproved /vs pages, blog metaTitle fields, Telemetry on the chat home, and end-to-end checkout attribution; the prior audit's "/vs/perplexity stays noindex" is correct.
8. Thirteen confirmed findings were lowered to Medium because they do not change what engines discover or what visitors do today: the Whop pixel, CSS and font weight, deploy gating, rendered-HTML crawl checks, the topics engine's one-page-per-term ceiling, template thinness, answers moderation, and the Study/Slides CTA gate.
9. The remaining Medium work clusters into a few files: pricing metadata (title omits Lite in page.tsx and en.ts), auth and beta-locale indexability policy (seo-indexing.test.ts forbids noindex), compositional JSON-LD duplicates with no rendered-page test, and the programmatic families' lack of pagination, indexes, moderation and IndexNow pings.
10. Implementation order below puts the eight High items first, grouped by file so each edit lands once, and then works through Medium items file by file; all Low items are polish and can follow at any pace.
