### 2. Show me the disagreement (done)
- `src/lib/disagreement-view.ts` builds the view from the pipeline's own fields only: compared positions (who held which stance, counts of models that responded), review findings (held / reworded / left out / kept as a minority view), and the recorded resolution. The synthesizer's stock sentence ("weighed the evidence...") is never shown as a reason: the view says "No specific reason for this choice was recorded". Missing models are named, not counted as dissent. Even split is called a split.
- `src/components/answer/DisagreementView.tsx`: columns by available width (auto-fit: stacked on phones, side by side when there is room, no device breakpoints), "Where they agree / differ", "Why this answer". Used in the app answer card and on shared pages (private and public). Share snapshots now carry the review findings (web checks excluded).
- Tests: `tests/disagreement-view.test.ts`, `e2e/split-view.e2e.ts` (side by side at 1280, stacked at 390 with no sideways scroll, stock-sentence honesty).

### 3. Verified answers with sources (BETA)
- Engine (`src/lib/orchestration/sourcing.ts`, wired in `orchestrator.ts`): for factual/research questions on paid plans, up to 3 checkable claims are picked from the WRITTEN answer by code (no extra model call), each is searched on the web (existing retriever: OpenRouter web plugin, engine pinned) and judged against the pages that came back. Per-claim state is supported / contradicted / unsettled only when at least one page was retrieved; otherwise "No source found". The card says when nothing was found, and why nothing ran otherwise.
- Free pool: Free never runs it. `liveEnv("free").retrievalEnabled` is false, Free deps have no retriever, and the plan gate refuses it anyway; the pool counter is unchanged by sourcing (tested). Free factual answers show: "Source checks run live web searches, so they are on paid plans. This answer was not checked against the web."
- Budget: the extra cost is estimated up front, counted in Keplar Usage, and the check is skipped (labelled) when it would not fit the allowance or the per-request cap. It never refuses an answer. Sensitive tier skips it. 20 s ceiling; a failed search says so.
- It is BETA and OFF until `KEPLAR_RETRIEVAL_ENABLED=true` (card: "Source checks are in BETA and are not switched on yet"). Nothing was live-tested against the real search API here (no key in this environment): the retriever path is covered with a recording retriever and a stubbed model API.
- Shared pages show a source check only if the server's HMAC signature verifies for that answer id (a browser cannot forge "supported" badges); tests cover forged / edited / other-answer / not-run checks.
- Pending: marketing and legal copy still says "Keplar does not look things up on the web yet" (landing, about, terms, developers page): update when the flag is turned on for real (those files belong to other workstreams); live smoke test with a real key; a "Verify" toggle in the composer; expanding claim picking beyond sentences with numbers/names (it is deliberately conservative).

### 8. Team workspaces (BETA, Business plan)
- Details and limits: `docs/teams.md`. A team is its own tenant (`tm_…`); shared projects, chats and sites live under the team id. Roles owner/admin/member/viewer; every opted-in route re-reads the caller's member row on every request, so removing a member (or the owner's plan lapsing) cuts access on the very next request. Personal data is never shared; routes not opted in always run personal (a test pins the list).
- Invites are drafts: saving one sends nothing; the owner/admin presses Send (email through the existing Resend `sendEmail`, with an honest "email isn't set up" when it isn't) or copies a one-time link (sha256 at rest, 7 days, single use, tied to the invited address).
- Shared allowance: Business only, max 10 members, ONE shared pool of 13,500 credits/month for the whole team, stated on the panel (proposals, `TODO(founder approval)` in `src/lib/team/policy.ts`). Audit log (newest 500, admin+), owner export, owner delete (typed name), leaving, account-deletion handling.
- Tests: `tests/team.test.ts` (14: roles matrix, draft/send/redeem, revocation, tenant isolation, export/delete, opt-in list), authz/rate-limit/privacy audits, `e2e/team.e2e.ts` (3).

### 9. Public API and browser extension (BETA)

Store text drafted in `extension/STORE_LISTING.md`; **nothing submitted anywhere**.
